01

产品概述

产品定位

DataRecord ChannelRx 是一款医疗器械渠道智能分析平台。

通过整合医疗器械企业内部采购数据、经销商出库数据、医院终端流向数据以及省级集采数据，帮助企业实时掌握经销商渠道健康状态，识别库存积压、异常流向、销售风险，并通过 AI 自动生成渠道分析报告。

核心价值主张

该产品不是简单的数据展示工具。核心价值在于：将医疗器械渠道管理过程中分散的数据，转化为可量化的经销商健康评价体系，帮助企业提前发现库存风险、渠道异常和终端销售变化。
02

背景与业务痛点

行业背景

医疗器械行业高度依赖经销商渠道。企业通常拥有以下五类数据：厂家销售数据、经销商采购数据、经销商出库数据、医院终端入院数据、省级集采数据。但这些数据来源分散，格式不统一，需要大量人工 Excel 整理。

当前痛点

🔍

无法判断经销商真实销售状态

厂家知道"经销商买了多少货"，但不知道"货是否真正销售到医院"。

📦

库存风险难以及时发现

经销商持续采购增长，但出库下降，可能意味着产品积压、需求下降或库存过高。

采购：100 → 120 → 150
出库：100 → 70 → 30
⚠️

数据异常难发现

出库量远大于采购量，可能存在跨区域窜货、数据遗漏或统计错误。

采购：100 / 出库：180

经销商健康评分模型

设计原则（V1.1 调整）：健康评分 只基于流向健康度（100 分制）。 采购稳定性、终端覆盖度降级为经销商详情页的展示指标，不参与总评分计算。 这样能让评分聚焦于"货是否真正流向终端"这一核心业务问题，避免多维度权重稀释核心信号。

总评分公式

Health Score = Flow Score
健康评分 = 流向健康度评分（0-100）

核心指标：出库比例

计算公式
出库比例 r = 经销商销售出库数量 / 厂家采购数量
偏离度  dev = |r - 1.0|

偏离度衡量出库比例偏离 100%（理想状态）的程度，是评分的唯一输入。

评分映射函数

出库比例区间偏离度 dev评分公式得分区间状态
80% – 120% dev ≤ 0.2 score = 100 − dev × 50 90 – 100 健康
70% – 80%
120% – 130%		 0.2 < dev ≤ 0.3 score = 90 − (dev − 0.2) × 300 60 – 89 预警
< 70%
> 130%		 dev > 0.3 score = max(0, 60 − (dev − 0.3) × 200) 0 – 59 异常

9.5 健康评分计算流程

触发时机：数据导入后手动触发（MVP 阶段）。

// 伪代码：评分计算引擎（V1.1 — 仅基于流向健康度）
function calculateHealthScore(dealerId, productType, month) {
  // 1. 取当月采购量与出库量
  const purchase  = getPurchaseSum(dealerId, productType, month)
  const shipment  = getShipmentSum(dealerId, productType, month)

  // 2. 计算出库比例与偏离度
  const ratio = purchase > 0 ? shipment / purchase : 0
  const dev   = Math.abs(ratio - 1)

  // 3. 健康评分 = 流向健康度评分（100 分制）
  const total = calcFlowScore(dev)
  const status = total >= 90 ? 'healthy'
              : total >= 60 ? 'warn'
              : 'risk'

  // 4. 详情页展示指标（不参与评分，独立计算）
  const stability = calcStability(...)     // 采购稳定性：趋势/环比/断月
  const coverage  = calcTerminalCoverage(...) // 终端覆盖度：医院数/渗透率

  return { total, ratio, status, stability, coverage }
}

// 流向健康度评分函数
function calcFlowScore(dev: number): number {
  if (dev <= 0.2)      return 100 - dev * 50                // 80-120%  → 90-100
  else if (dev <= 0.3) return 90 - (dev - 0.2) * 300         // 70-80%/120-130% → 60-89
  else               return Math.max(0, 60 - (dev - 0.3) * 200) // <70%/>130% → 0-59
}
边界说明：若 purchase = 0（当月无采购），ratio 设为 0，score = 0，状态为异常 — 表示经销商本月无进货但可能有出库，需人工核查。

-- 医院
CREATE TABLE hospitals (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  hospital_name TEXT NOT NULL,
  province      TEXT NOT NULL,
  city          TEXT,
  hospital_level TEXT,  -- 三甲 / 三乙 / 二甲 ...
  created_at    TIMESTAMPTZ DEFAULT now(),
  UNIQUE(hospital_name, province)
);

-- 产品
CREATE TABLE products (
  id    UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  code  TEXT UNIQUE NOT NULL,  -- ultrasound | stapler
  name  TEXT NOT NULL
);

原始数据表（4 类来源）

-- 1. 厂家采购数据
CREATE TABLE manufacturer_sales (
  id                 UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  dealer_id          UUID REFERENCES dealers(id),
  product_id         UUID REFERENCES products(id),
  month              TEXT NOT NULL,  -- 'YYYY-MM'
  purchase_quantity  NUMERIC NOT NULL,
  created_at         TIMESTAMPTZ DEFAULT now(),
  UNIQUE(dealer_id, product_id, month)
);

-- 2. 经销商出库数据（核心）
CREATE TABLE dealer_shipments (
  id                 UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  dealer_id          UUID REFERENCES dealers(id),
  hospital_id        UUID REFERENCES hospitals(id),
  product_id         UUID REFERENCES products(id),
  month              TEXT NOT NULL,
  shipment_quantity  NUMERIC NOT NULL,
  source_type        TEXT NOT NULL CHECK (source_type IN ('invoice','delivery_note','inventory_report')),
  created_at         TIMESTAMPTZ DEFAULT now()
);

-- 3. 医院终端入院数据
CREATE TABLE hospital_intakes (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  hospital_id UUID REFERENCES hospitals(id),
  dealer_id   UUID REFERENCES dealers(id),
  product_id  UUID REFERENCES products(id),
  month       TEXT NOT NULL,
  quantity    NUMERIC NOT NULL,
  province    TEXT,
  created_at  TIMESTAMPTZ DEFAULT now()
);

-- 4. 省级集采数据（配送商 ≠ 经销商）
CREATE TABLE procurement_data (
  id               UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  hospital_id      UUID REFERENCES hospitals(id),
  product_id       UUID REFERENCES products(id),
  delivery_company TEXT NOT NULL,
  province         TEXT NOT NULL,
  month            TEXT NOT NULL,
  quantity         NUMERIC NOT NULL,
  created_at       TIMESTAMPTZ DEFAULT now()
);

计算结果表（评分 + 风险 + AI 报告）

-- 健康评分（按 经销商 × 产品 × 月 粒度）
-- V1.1: total 仅基于流向健康度，stability/coverage 为详情页展示指标
CREATE TABLE health_scores (
  id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  dealer_id    UUID REFERENCES dealers(id),
  product_id   UUID REFERENCES products(id),
  month        TEXT NOT NULL,
  total        NUMERIC,        -- 0-100，仅基于流向健康度
  shipment_ratio NUMERIC,      -- 出库比例 = shipment / purchase
  stability    NUMERIC,        -- 展示用：采购稳定性指标（不参与 total）
  coverage     NUMERIC,        -- 展示用：终端覆盖度指标（不参与 total）
  status       TEXT CHECK (status IN ('healthy','warn','risk')),
  calculated_at TIMESTAMPTZ DEFAULT now(),
  UNIQUE(dealer_id, product_id, month)
);

-- 风险预警
CREATE TABLE risk_alerts (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  dealer_id   UUID REFERENCES dealers(id),
  product_id  UUID REFERENCES products(id),
  risk_type   TEXT CHECK (risk_type IN ('inventory','abnormal','decline')),
  severity    TEXT CHECK (severity IN ('low','medium','high')),
  context     JSONB,            -- 触发时的数据快照
  triggered_at TIMESTAMPTZ DEFAULT now(),
  resolved_at TIMESTAMPTZ
);

-- AI 报告
CREATE TABLE ai_reports (
  id         UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  scope      TEXT,  -- region | dealer | product
  scope_value TEXT,  -- '江苏' / dealer_id / 'ultrasound'
  period     TEXT,  -- week | month
  period_value TEXT, -- '2026-W30' / '2026-07'
  content    TEXT,  -- Markdown 报告内容
  model      TEXT,  -- 'deepseek-chat'
  token_usage JSONB,
  created_at TIMESTAMPTZ DEFAULT now()
);

评分模型简化为仅基于流向健康度
已确认 · 调整
健康评分 = 流向健康度评分（100 分制）。采购稳定性、终端覆盖度降级为经销商详情页的展示指标，不参与总评分计算。评分聚焦于"货是否真正流向终端"这一核心问题。
健康状态采用三档划分
已确认 · 选项 A
三档：健康（≥90）/ 预警（60-89）/ 异常（<60）。与 PRD 原始设计一致，简洁清晰。
AI 模型使用 DeepSeek
已确认 · 选项 A
DeepSeek API，成本约为 OpenAI 的 1/10，适合 MVP 阶段。AI 仅负责报告总结/解释/建议，不参与数值计算。
MVP 不需要登录认证
已确认 · 选项 A
面试演示场景下免登录更顺，所有 API 直接公开访问。后续如需多租户再补 Supabase Auth。
